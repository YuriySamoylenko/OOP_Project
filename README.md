# OOP Project
# Project Management Service
# Project Management System (PMS) — Сервіс для управління проєктами

Сучасний кросплатформений вебдодаток для автоматизації процесів планування, розподілу завдань та контролю командної розробки програмного забезпечення. Проєкт виконано в межах курсового проєкту з дисципліни **«Об’єктно-орієнтоване програмування»**.

Основна мета проєкту — демонстрація практичного застосування об'єктно-орієнтованої парадигми (ООП), SOLID-принципів та системних технологій платформи .NET.

---

## 🚀 Технологічний стек

* **Платформа:** .NET 8 (C# 12)
* **Презентаційний шар:** Blazor Server (InteractiveServer mode) + Bootstrap 5
* **Рівень доступу до даних:** Entity Framework Core + SQL Server (або СУБД за вибором)
* **Тестування:** MSTest + Moq (ізоляція залежностей через Mocking)

---

## 🏗️ Архітектура проєкту (Архітектура шарів)

Додаток побудовано за класичною трьохшаровою архітектурою з чітким розділенням обов'язків (Separation of Concerns):

1. **Pms.Core (Domain Layer):** Незалежне ядро системи. Містить описи бізнес-сутностей, системні перерахування (Enums) та інтерфейси сховищ даних (`IRepository<T>`).
2. **Pms.Bll (Business Logic Layer):** Шар бізнес-логіки. Включає інтерфейси та реалізації сервісів (управління проєктами, завданнями, учасниками), логіку валідації прав доступу, а також утиліти серіалізації.
3. **Pms.Web (Presentation Layer):** Інтерфейс користувача на Blazor Server. Містить Razor-компоненти, сторінки, кастомні статичні розширення для UI та систему глобальних сповіщень.
4. **Pms.Tests (Testing Layer):** Модульні тести для перевірки бізнес-логіки системи в ізоляції від бази даних.

## 🛠️ Демонстрація застосування принципів ООП та технологій .NET

Проєкт у повному обсязі втілює 10 ключових вимог об'єктно-орієнтованого проєктування та платформи .NET:

### 1. Інкапсуляція (Encapsulation)
* **На рівні даних:** Стан усіх сутностей захищено за допомогою автоматичних та кастомних властивостей з модифікаторами `get` та `set`. Прямий доступ до полів закритий.
* **На рівні поведінки:** Логіку перевірки прав доступу інкапсульовано безпосередньо всередині об'єктів сутностей (методи `CanManage...()`). Зовнішній код не аналізує внутрішні поля об'єкта, а запитує його готовність виконати дію (*"Tell, Don't Ask"*).

### 2. Статичні члени класів (Static Members)
* Реалізовано статичний клас `EnumExtensions` у шарі презентації. Він містить статичні методи розширення (`this Status status`), які без виділення пам'яті в купі (Heap) динамічно маплять системні енуми у відповідні CSS-класи Bootstrap для рендерингу UI.

### 3. Інтерфейси (Interfaces)
* Використовуються для реалізації принципу інверсії залежностей (DIP із SOLID). 
* Приклади в коді: `IRepository<T>` (абстрагування від Entity Framework), `ITaskService`, `IProjectService`, `INotificationService`. Шар UI взаємодіє виключно з інтерфейсами бізнес-сервісів.

### 4. Абстрактні класи (Abstract Classes)
* **`BaseEntity`:** Абстрактна сутність, яка унеможливлює створення пустих об'єктів та гарантує наявність обов'язкового первинного ключа `Id` для всієї доменної моделі.
* **`User`:** Абстрактний базовий профіль користувача, що розширює `IdentityUser` та задає дефолтну структуру прав безпеки.

### 5. Спадкування (Inheritance)
* Реалізує відношення типу «Is-A» та забезпечує повторне використання коду:
  * Ієрархія користувачів: `SystemAdmin : User`.
  * Ієрархія учасників проєкту: `Manager : Participant` та `Member : Participant`.
  * Усі сутності бази даних успадковують властивості від `BaseEntity`.

### 6. Поліморфізм (Polymorphism)
* Використано поліморфне заміщення поведінки (Method Overriding) в рантаймі. Похідні класи `SystemAdmin` та `Manager` перевизначають (`override`) віртуальні методи базових класів `User` та `Participant` для надання специфічних прав доступу до ресурсів системи.

### 7. Делегати та події (.NET Delegates & Events)
* Побудовано кастомну підсистему глобальних сповіщень про помилки на основі патерну «Видавець-Підписник». 
* Сервіс `NotificationService` оголошує подію `public event Action<string>? OnErrorMessage;` на базі системного делегата `Action<T>`. Компонент `NotificationDisplay.razor` підписується на неї при ініціалізації та обов'язково відписується у методі `Dispose()` інтерфейсу `IDisposable` для запобігання витокам пам'яті.

### 8. Серіалізація / Десеріалізація об'єктів
* Реалізовано функціонал експорту та імпорту завдань у формат JSON за допомогою `System.Text.Json`. 
* Для уникнення помилок циклічних посилань Entity Framework, сутність `PmsTask` трансформується у плаский DTO-об'єкт `TaskModel`. Метод `JsonSerializer.Serialize` виконує експорт у файл, а `JsonSerializer.Deserialize` — відновлює стан об'єкта з файлу під час імпорту.

### 9. Узагальнені колекції (Collections.Generic)
* Усі навігаційні властивості «один-до-багатьох» всередині сутностей (наприклад, списки спринтів та завдань у проєкті) оголошені як `IList<T>` та ініціалізовані через `List<T>`. Це забезпечує сувору типізацію на етапі компіляції та усуває витрати на boxing/unboxing.

### 10. Технологія LINQ (Language Integrated Query)
* Активно застосовується в сервісному шарі (`BLL`) для виконання операцій фільтрації, сортування та проектування даних доменних моделей. Лямбда-вирази транслюються через EF Core в оптимізовані SQL-запити.

## 👥 Ролі користувачів та модель прав доступу

Система гнучко розділяє права доступу користувачів на двох рівнях (глобальний рівень та рівень конкретного проєкту):

| Роль | Керування користувачами проекта | Створення проєктів | Управління спринтами проєкту | Робота із завданнями |
| :--- | :---: | :---: | :---: | :---: |
| **SystemAdmin** | ✅ Так | ✅ Так | ✅ Так | ✅ Так |
| **Manager** (у проєкті) | ❌ Ні | ❌ Ні | ✅ Так | ✅ Так |
| **Member** (у проєкті) | ❌ Ні | ❌ Ні | ❌ Ні | ✅ Так |

## 🧪 Тестування системи

### Модульне тестування (Unit Tests)
Проєкт покритий автоматизованими тестами бізнес-рівня за допомогою фреймворку **MSTest** та бібліотеки **Moq**. Тести перевіряють:
* Коректність створення, оновлення та видалення завдань.
* Захист методів бізнес-сервісів від користувачів без належних прав доступу.
* Валідацію моделей даних (DTO) через `DataAnnotations`.
* Логіку роботи серіалізації/десеріалізації (експорт/імпорт JSON).
